# 当前能力与目标架构

> 状态：本章是实现边界的权威说明。
> 阅读约定：“当前 main”表示基线 `ea13e52` 已有能力；“第一版目标”表示待实现架构。

## 能力边界

当前代理已经具备 Profile、单 Upstream 转发、部分视觉增强、过载重试和运行统计。智能路由不是对这些能力的重命名，而是在其上增加新的策略层。

![当前模块与目标模块](/diagrams/current-modules.svg)

| 能力 | 当前 `main` | 第一版目标 | 未来方向 |
|---|---|---|---|
| 显式模型转发 | 已有 | 保持原行为 | 不变 |
| `model=auto` | 没有 | 读取已发布策略并选方案 | 扩展更多 API |
| Profile Upstream | 每个 Profile 一个 | 保持一个 | Route Target 与多提供方 |
| 视觉增强 | Anthropic Messages、OpenAI Responses 主请求已有 | 在选定执行方案后运行 | 更多协议与视觉方案 |
| OpenAI 识图接口 | Responses 主请求可选 Chat Completions 或 Responses 作为识图子请求 transport | 保持该选择，不改变主请求协议 | 更多可插拔视觉接口 |
| Responses 工具输出图片 | 已重写 `function_call_output.output[]` 中的直接 `input_image` | 纳入执行方案能力判断 | 更多嵌套容器 |
| Chat Completions 图片 | 主请求保持原样，可转发给原生视觉模型 | 不提供组合增强 | 可增加组合视觉 |
| `overload_rules` 重试 | 已有 | 纳入总尝试和总截止时间 | Target 级重试 |
| 重试耗尽后的额外发送 | 当前存在 | 必须移除 | 不再支持 |
| 模型切换 | 没有 | 同模型重试耗尽后按策略切换 | 跨提供方同模型切换 |
| 会话模型固定 | 没有 | 使用 `X-LLM-Session-ID` | 可扩展更多显式会话协议 |
| 质量与成本估计 | 没有 | 分层质量后验与完整成本估计 | 可替换算法模块 |
| 动态策略优化 | 没有 | 异步对照、评审、候选生成 | 更丰富可靠反馈 |
| 策略灰度与回滚 | 没有 | 不可变快照与部署记录 | 分布式通知 |
| 视觉内容日志 | `INFO` 记录最多 4096 个 Unicode 字符的视觉描述或非成功响应正文 | 默认关闭内容正文，或由管理员显式开启并控制访问与留存 | 可接入专用敏感日志通道 |
| 存储 | SQLite | 第一版继续使用 | PostgreSQL |

## 协议支持矩阵

第一版只接入当前协议中带 `model` 的主要生成路由。

| API | 显式模型 | `model=auto` | 原生视觉 | 组合视觉增强 |
|---|---:|---:|---:|---:|
| Anthropic `POST /v1/messages` | 支持 | 目标支持 | 取决于模型 | 已有路径，需调整顺序 |
| OpenAI `POST /v1/chat/completions` | 支持 | 目标支持 | 取决于模型 | 第一版不支持 |
| OpenAI `POST /v1/responses` | 支持 | 目标支持 | 取决于模型 | 已有路径；识图 transport 可选 Chat Completions 或 Responses，需调整执行顺序 |
| 其他代理路由 | 保持现状 | 返回明确错误 | 保持现状 | 不新增 |

在不支持的路由上发送：

```json
{"model": "auto"}
```

应返回可诊断的 `4xx` 错误，而不是静默改成默认模型。

## 关键调用顺序变化

### 当前视觉路径

当前视觉预处理位于路由之前，并读取请求中的具体模型决定是否增强。这适合显式模型，但 `auto` 在路由前没有具体模型。

OpenAI 的增强入口是 Responses 主请求。它会处理用户消息 `content[]` 和 `function_call_output.output[]` 中的直接 `input_image`，再把结果写回原容器；识图子请求可由 Profile 选择 Chat Completions 或 Responses transport。这个选项只改变识图子请求接口，不会把 Responses 主请求改成 Chat Completions。Chat Completions 主请求目前只会原样转发，不进入组合视觉增强。

### 目标路径

目标架构先只读提取图片数量、媒体类型等元数据，然后完成模型和视觉方案选择，最后执行原图直传或视觉增强：

```text
读取图片元数据
  -> 选择执行方案
  -> 确定具体主模型
  -> 原生视觉直传 / 生成视觉证据
  -> 转发
```

显式模型仍使用现有视觉路径，避免改变已有调用契约。

## 当前重试缺口

当前代理在重试预算耗尽后会再发送一次请求，以取得最终错误响应。这个额外请求会造成三个问题：

1. 实际尝试次数多于配置；
2. 成本统计偏低；
3. 智能切换无法可靠控制整体截止时间。

第一项实现工作必须移除该调用，直接保留并返回最后一次已收到的错误响应。

## 第一版的单 Upstream 限制

第一版所有参与模型必须由当前 Profile 的同一个 Upstream 和协议提供。以下配置不是第一版含义：

```text
模型 A -> Provider 1
模型 A -> Provider 2
模型 B -> Provider 3
```

将来若支持该模式，需要新增 Route Target、模型到 Target 的映射、Target 级价格和健康状态，不能把现有 Upstream 字段隐式解释成节点池。
