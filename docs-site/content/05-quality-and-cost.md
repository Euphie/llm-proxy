# 质量与成本

> 状态说明：当前 `main` 记录部分重试与请求统计，但没有统一的质量估计、成本模型和发布门槛。本章均为目标设计。

智能路由的目标不是选择最便宜的模型，而是在质量约束下最小化业务请求的预期总成本。质量约束是硬门槛，成本是通过门槛后的排序因素。

## 质量定义

每个有效评估样本按四个维度计分：

| 维度 | 权重 | 关注点 |
| --- | ---: | --- |
| 正确性 | 0.40 | 事实、推理和最终结论是否正确 |
| 指令遵循 | 0.25 | 是否满足格式、约束和用户要求 |
| 完整性 | 0.20 | 是否覆盖完成任务所需的关键内容 |
| 安全性 | 0.15 | 是否避免危险、泄露或不当输出 |

综合质量分数为：

```text
Q = 0.40 × correctness
  + 0.25 × instruction_following
  + 0.20 × completeness
  + 0.15 × safety
```

不同任务类型分别维护质量后验分布。在线选择使用保守估计，而不是只看平均分，避免少量幸运样本让弱模型被过早放量。

## 分层贝叶斯质量估计

`bayesian-v1` 不训练神经网络，也不维护一个全局“模型权重”。它按以下层级估计每个执行方案
相对强模型基线的质量分布：

```text
Profile × 任务类型 × 特征区间 × 执行方案
                     ↓ 样本不足时收缩
Profile × 任务类型 × 执行方案
                     ↓ 仍不足时收缩
Profile × 模型全局先验
```

- 确定性格式、协议、工具结构和业务检查提供最高权重证据；
- 匿名成对评审按置信度折算为有效胜、负或平局样本；
- 小样本估计向任务级与模型全局先验收缩，防止少量偶然胜出被放大；
- 旧样本按时间衰减，价格不变但模型服务质量发生漂移时，近期证据会逐步占主导；
- 在线路由读取后验分布的保守分位数，发布则检查完整的非劣概率，而不是只比较均值。

因此，新模型开始时会接近可信先验并保持保守；只有累积足够、覆盖当前任务分布的证据后，
才会获得更高流量。先验、衰减参数和保守分位点都写入不可变策略，确保结果可复现。

## 质量发布门槛

候选策略相对于强基线必须满足：

```text
P(Q_candidate / Q_baseline >= 0.98) >= 0.95
```

此外还要同时满足：

- 至少 300 个有效成对比较样本。
- 每个主要任务类型至少 30 个有效样本。
- 严重错误率的 95% 后验上界低于 1%。
- 没有未处理的安全性或数据泄露事件。

样本不足时，策略只能停留在评估状态，不能因为点估计较好而发布。

## 预期总成本

业务请求的成本估计必须覆盖完整链路：

```text
ExpectedTotalCost =
  TaskAnalyzerCost
  + MainModelCost
  + VisionCost
  + P(retry) × RetryCost
  + P(switch) × FallbackCost
```

其中：

- 输入、缓存输入和输出按模型目录中的单价分别计算。
- 重试概率、切换概率来自近期按任务类型和模型聚合的运行指标。
- 动态评估产生的对照回答和质量评审成本单独记账，不掺入业务请求成本。
- 价格使用整数微美元存储，避免浮点累计误差。

## 计划比较示例

假设某个编码任务有三个可执行计划：

| 计划 | 质量比的保守估计 | 预期业务成本 | 结论 |
| --- | ---: | ---: | --- |
| Fast | 0.965 | $0.006 | 未达到 0.98，淘汰 |
| Balanced | 0.986 | $0.011 | 通过，成本最低 |
| Strong | 1.000 | $0.024 | 通过，作为强基线 |

最终选择 `Balanced`。即使 `Fast` 更便宜，也不能越过质量硬门槛。

## 优化器决策顺序

1. 能力硬过滤。
2. 应用会话绑定与只升不降规则。
3. 计算各计划的质量保守估计。
4. 淘汰低于质量门槛的计划。
5. 在剩余计划中选择预期总成本最低者。
6. 若统计不可信、结果并列或全部淘汰，选择强基线。

## 统计口径

| 数据 | 分组维度 | 用途 |
| --- | --- | --- |
| 请求成功率 | profile、任务类型、模型、策略版本 | 健康过滤和重试估计 |
| 首 token/总延迟 | 同上 | 观测运行影响，不直接替代质量 |
| token 与费用 | 模型、视觉计划 | 成本估计 |
| 成对评估结果 | 任务类型、候选、基线 | 质量后验 |
| 严重错误 | 策略版本、任务类型 | 发布硬门槛 |

延迟可以作为产品侧附加约束，但不能把“回答更快”直接当作“回答质量更高”。

## 验收检查

- [ ] 质量分数使用固定四维权重。
- [ ] 质量估计按 Profile、任务、特征和执行方案分层。
- [ ] 小样本向先验收缩，旧样本时间衰减，在线选择使用保守分位数。
- [ ] 发布同时检查概率门槛、样本量和严重错误上界。
- [ ] 成本包含分析、主模型、视觉、重试和切换。
- [ ] 评估成本与业务成本分账。
- [ ] 价格和费用以整数微美元存储。
- [ ] 没有计划通过质量门槛时回退到强基线。
