# 运行时可靠性

> 状态说明：当前 `main` 已有过载规则、重试和统计，但重试耗尽后可能额外发送一次请求。目标实现必须先修复该问题，再加入会话绑定、模型切换和统一总预算。

运行时可靠性负责把不可变执行计划安全地跑完。它必须限制尝试次数、尊重客户端取消，并确保流式响应开始后不再切换模型。

## 会话绑定

客户端可显式传入：

```http
X-LLM-Session-ID: project-a-conversation-42
```

该值最大 256 字节，不转发给上游。存储键使用 HMAC：

```text
binding_key = HMAC(server_secret, profile_id || ":" || session_id)
```

数据库不保存原始会话 ID。绑定在 30 天无活动后过期。

| 属性 | 目标行为 |
| --- | --- |
| 绑定内容 | 策略版本、模型角色、实际模型 |
| 首次请求 | 按当前部署和路由结果建立绑定 |
| 后续请求 | 优先沿用绑定 |
| 自动升级 | 能力不足、上下文不足、模型不健康或执行失败时允许 |
| 自动降级 | 不允许 |
| 显式模型 | 不使用 `auto` 会话绑定 |

只升不降可以避免同一会话在强弱模型之间来回跳动，导致风格和能力不稳定。

## 视觉执行计划

视觉处理必须在路由计划确定后执行，因为不同主模型可能使用不同视觉方案。

![视觉执行计划](/diagrams/vision-plans.svg)

| 模式 | 处理方式 | 适用接口 |
| --- | --- | --- |
| `none` | 不处理图片 | 无图片请求 |
| `native` | 图片直接交给主模型 | 三个受支持接口 |
| `composite` | 视觉模型先生成描述，再交给文本主模型 | Anthropic Messages、OpenAI Responses |

OpenAI Chat Completions 在首版只支持原生视觉，不执行复合视觉。目标实现把视觉描述视为
请求级临时数据，默认不写普通日志；当前基线的敏感日志例外见下文。

当前 `main@ea13e52` 还有一个容易混淆的能力：OpenAI Responses 主请求进入图片预处理后，
`vision.transport` 可选择用 Chat Completions 或 Responses 发起识图子请求。这只改变
识图请求的传输格式，不会选择主回答模型，也不是智能路由。目标路由仍需先选定执行计划，
再决定原生视觉或复合视觉。

复合计划示例：

```json
{
  "mode": "composite",
  "vision_model": "vision-primary",
  "text_model": "balanced-text",
  "max_description_tokens": 800
}
```

## 重试与模型切换

重试和切换是两个不同动作：

| 动作 | 模型 | 请求体 | 触发条件 |
| --- | --- | --- | --- |
| 同模型重试 | 不变 | 不变 | 可重试的超时、限流或过载 |
| 模型切换 | 改为后备计划 | 语义内容不变，仅做协议适配 | 同模型预算耗尽或模型不健康 |

默认限制：

```text
max_model_switches = 1
max_total_attempts = 4
```

所有尝试共享一个请求总超时。计数器必须在每次发起上游调用前原子递增，循环退出后不得再发送“最后一次”请求；这正是当前 `main` 需要先修复的边界。

推荐执行顺序：

1. 获取执行计划和总截止时间。
2. 调用首选模型。
3. 对可重试错误按同一模型、同一请求体重试。
4. 同模型预算耗尽后，最多切换一次。
5. 达到总次数或总截止时间后返回最终错误。

## 流式响应

流式请求在向客户端写出第一个响应字节前，可以按普通规则重试或切换。一旦开始写流：

- 不再重试。
- 不再切换模型。
- 上游错误以当前协议允许的方式结束流。
- 客户端取消必须立即传递到任务分析、视觉和主模型调用。

这样可避免把两个不同模型的输出拼接成一个不可解释的响应。

## 故障处理

| 场景 | 目标行为 |
| --- | --- |
| 会话绑定模型失效 | 升级到满足能力的健康模型并更新绑定 |
| 视觉调用失败 | 按计划定义返回错误或切换到原生视觉，不临时编造新方案 |
| 总超时耗尽 | 取消所有子调用并返回统一超时 |
| 客户端取消 | 立即停止后续重试、切换和评估采样 |
| 流已经开始 | 只结束当前流，不发起新上游请求 |

## 缓存边界

### 当前视觉缓存

当前实现为每个 Profile Handler 创建独立的进程内 TTL + LRU 缓存。默认 TTL 为 30 分钟、
容量为 512 条；TTL 从成功结果写入时计算，缓存命中只更新 LRU 顺序，不延长过期时间。失败
结果不缓存，同一键的并发未命中会合并为一次识图请求。

缓存键是进程随机密钥保护的 HMAC，覆盖：

- Profile；
- 视觉 `transport` 与视觉模型；
- 实际识图提示词，包括同一条用户消息中最多 4096 字符的问题上下文；
- 图片来源类型与内容：base64 媒体类型和数据、URL/data URL、`file_id`，以及 Responses
  的 `detail`；
- 该协议实际允许透传的鉴权、版本、Organization 和 Project 请求头及其全部值。

因此，图片、问题、提示词、视觉模型、调用接口或鉴权域任一不同都会形成新条目。保存该
Profile 导致 Handler 重建、运行时全量重载或进程重启时，缓存都会清空；缓存不写入 SQLite，
也不在实例之间共享。

### 目标路由缓存

| 缓存 | 隔离键与切换行为 |
|---|---|
| 路由决策缓存 | 必须包含 Profile 与规范策略版本；发布、灰度或回滚后不能复用旧版本决策 |
| Upstream Prompt Cache | 只按实际提供方和实际模型统计；切换模型视为旧缓存不可用，其损失计入成本 |
| 响应结果 | 不跨模型复用 |
| 视觉证据缓存 | 不以策略版本为键；继续按图片、视觉模型、transport、提示词、问题上下文和鉴权域隔离 |
| 历史策略快照缓存 | 按 Profile 与规范策略版本读取不可变快照，供仍绑定旧版本的会话使用 |

模型或视觉方案切换时必须从原始请求重新生成派生正文。若视觉模型、transport、提示词或
问题上下文改变，视觉缓存自然未命中；只有视觉方案完全相同时才可安全复用已有证据。文本
主模型一旦切换，不能推定它仍能命中上一模型的 Prompt Cache。

## 验收检查

- [ ] 重试耗尽后不会额外发送请求。
- [ ] 总尝试次数不超过 4，模型切换默认不超过 1 次。
- [ ] 所有子调用共享总截止时间并响应取消。
- [ ] 流开始后不重试、不切换。
- [ ] 原始会话 ID 不入库、不转发。
- [ ] Chat Completions 不启用复合视觉。
- [ ] 当前视觉缓存的 TTL、LRU、键和重建失效边界可解释。
- [ ] 路由决策、Prompt Cache、视觉证据和历史策略快照不会跨错误边界复用。
