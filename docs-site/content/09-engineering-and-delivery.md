# 工程实现与交付

> 状态说明：本章给出从当前 `main` 演进到目标系统的工程边界、数据模型和分阶段交付顺序。按项目约束，不考虑旧 profile 的历史兼容；升级后旧 profile 默认关闭智能路由，并应在发布说明中明确提示。

实现应先修正现有代理边界，再逐步引入在线路由和异步优化。任何阶段都必须能独立回退到显式模型代理。

## 模块边界

| 模块 | 核心职责 |
| --- | --- |
| `proxy` | 协议适配、总超时、上游调用、重试、切换、响应写入 |
| `router` | 特征抽取、任务分析、能力过滤、返回不可变计划 |
| `catalog` | 模型能力、价格、上下文和健康信息 |
| `vision` | 执行原生或复合视觉计划 |
| `strategy` | 快照、部署、状态机、发布与回滚 |
| `evaluation` | 非阻塞采样、预算、对照回答、质量评审和聚合 |
| `storage` | SQLite 持久化和事务边界 |
| `admin` | profile、策略、部署、指标和审计 API |

Router 不发送上游请求；Proxy 不在执行过程中重新做策略优化。

## 建议接口

```go
type Router interface {
	Route(ctx context.Context, req RequestFeatures) (ExecutionPlan, RouteTrace, error)
}

type StrategyStore interface {
	ActiveSnapshot(ctx context.Context, profileID string) (*StrategySnapshot, error)
	CompareAndSwapDeployment(
		ctx context.Context,
		profileID string,
		expectedRevision int64,
		next Deployment,
	) error
}

type EvaluationQueue interface {
	TryEnqueue(sample EvaluationSample) bool
}
```

`TryEnqueue` 必须立即返回。队列满时丢弃评估样本，而不是拖慢用户请求。

## 数据模型

![数据模型](/diagrams/data-model.svg)

| 表 | 关键内容 | 保留原则 |
| --- | --- | --- |
| `routing_strategies` | 不可变快照、状态、父版本 | 长期保留用于审计 |
| `routing_strategy_deployments` | stable/canary 指针、比例、revision | 保留部署历史 |
| `routing_strategy_events` | 状态变更、发布、回滚原因 | 只追加 |
| `routing_session_bindings` | Session ID HMAC 摘要、策略、模型、最后活动时间 | 30 天无活动过期 |
| `routing_request_metrics` | 延迟、token、费用、结果代码 | 不含提示词和回答 |
| `routing_evaluation_samples` | 脱敏元数据、A/B 结果、置信度 | 受保留期控制 |
| `routing_quality_aggregates` | 分任务类型的后验统计 | 可重建、版本化 |
| `routing_daily_budgets` | 业务/评估预算的预留和结算 | 按日审计 |

SQLite 事务应覆盖预算预留、发布 CAS 和状态变化；这些操作不能靠进程内先读后写模拟。

## 敏感数据

| 数据 | 普通日志 | 数据库 | 内存 |
| --- | --- | --- | --- |
| 调用方与 Upstream 凭据 | 禁止 | 禁止 | 仅当前请求衍生的内存上下文或有界内存评估任务按协议白名单使用 |
| 原始提示词/回答 | 禁止 | 默认禁止 | 请求与评估期间允许 |
| 原始 Session ID | 禁止 | 禁止 | 计算 HMAC 时短暂允许 |
| Session ID HMAC 摘要 | 可用截断形式 | 允许 | 允许 |
| 路由原因、策略版本 | 允许 | 允许 | 允许 |
| 脱敏评估结果 | 允许低基数摘要 | 允许 | 允许 |
| 视觉描述与 Upstream 错误正文 | 当前 `main` 以 `INFO` 最多记录 4096 个 Unicode 字符；目标默认关闭正文，显式开启时按敏感日志管理 | 禁止 | 视觉处理期间允许 |

凭据不进入 Profile 或任何持久化存储。任务判断、视觉、主模型、对照回答和质量评审只复用当前请求携带的协议白名单鉴权头；异步任务完成、超时或被丢弃后必须释放对应内存。内部错误不得把完整请求体或密钥拼入日志。

当前 `main` 的 `vision.debug.description` 和 `vision.debug.upstream_response` 会以 `INFO` 输出视觉描述或非成功响应正文，截断上限为 4096 个 Unicode 字符；这些内容可能包含用户文本，必须视为敏感日志。目标实现应默认关闭正文记录，只有管理员显式开启后才允许输出，并同时配置访问、留存和导出边界。智能路由本身不新增提示词、回答、对照回答或评审正文日志。

## 可观测性

至少提供以下低基数指标：

- 按 profile、策略版本和模型角色统计请求量。
- 任务分析失败与低置信度回退量。
- 能力过滤淘汰原因。
- 重试、模型切换、总预算耗尽和流中断次数。
- 会话绑定命中、升级与过期次数。
- 评估队列长度、丢弃、预算拒绝和无效样本。
- 策略灰度、回滚和发布门槛失败次数。

追踪可记录调用阶段与耗时，但不记录用户内容。

## 分阶段交付

| 阶段 | 交付内容 | 关键验收 |
| ---: | --- | --- |
| 1 | 修复当前重试边界，统一总尝试计数；为视觉内容日志增加显式开关 | 无额外请求；默认日志不含视觉描述和错误正文 |
| 2 | 模型目录、角色、能力与价格配置 | 配置校验和微美元计价通过 |
| 3 | `model=auto` 入口与协议限制 | 显式模型无回归，其他接口明确报错 |
| 4 | 特征抽取、任务分析、能力过滤 | 失败回退强基线 |
| 5 | 质量/成本估计与不可变执行计划 | 质量硬门槛先于成本 |
| 6 | 会话绑定、视觉计划、模型切换 | 只升不降，流开始后不切换 |
| 7 | 策略快照、灰度、CAS 发布与回滚 | 并发发布和在途快照正确 |
| 8 | 异步动态评估、预算与质量评审 | 不阻塞在线请求，不泄露内容 |
| 9 | 管理 API、观测、压力与故障演练 | 达到完整上线门槛 |

每个阶段应同时包含数据库迁移、单元测试、集成测试和回滚说明。由于不提供历史兼容，迁移应显式把既有 profile 的智能路由设置为关闭，等待管理员完成新配置。

## 测试重点

| 测试层级 | 场景 |
| --- | --- |
| 单元测试 | token 估算、能力过滤、质量公式、费用、状态转换 |
| 属性测试 | 总尝试次数、只升不降、CAS revision 单调性 |
| 集成测试 | 三种协议、视觉计划、流式、取消、上游过载 |
| 并发测试 | 会话绑定、预算预留、策略发布和队列满载 |
| 故障注入 | 分析超时、SQLite 忙、上游断流、质量评审冲突 |
| 安全测试 | Header 白名单、凭据不持久化；视觉正文默认关闭，显式开启时按 4096 Unicode 字符截断 |

## 上线门槛

- [ ] 显式模型请求无行为回归。
- [ ] `auto` 只开放给三个规定接口。
- [ ] 当前重试耗尽额外调用问题已修复。
- [ ] 在线路由在策略、统计或分析异常时可回退强基线。
- [ ] 总超时、总尝试、流式和客户端取消边界经过故障测试。
- [ ] 动态评估不会阻塞业务，也不会超出每日预算。
- [ ] 策略发布、灰度和回滚具有完整审计记录。
- [ ] 日志和持久化扫描未发现密钥、提示词或原始回答。
- [ ] 文档明确提示：旧 profile 默认不启用智能路由，不保证历史配置兼容。
