## 吸收的优点

- 借鉴 LiteLLM、Helicone 的 Target 负载、容量和健康调度思路。
- 借鉴 TensorZero 的 ClientCommit、稳定实验和强类型反馈。
- 借鉴 vLLM Semantic Router 与 RouteLLM 的规则、任务判断和离线校准思路。
- 借鉴 Cloudflare 的草稿、发布、灰度和回滚生命周期。
- 借鉴 OpenRouter 等产品对能力、地域、价格和数据策略的明确约束。

## 明确不照搬

1. 不采用任意递归的策略图，避免重试、回退和辅助调用组合成失控链路。
2. 不把不同供应商或外部产品中的 Provider group 映射成跨 Profile 候选。
3. 不在一次请求中运行无上限的并行模型比较。
4. 不让评测结果自动发布，也不让一个综合分数绕过质量硬门槛。
5. 不把市场宣传或默认阈值当作本项目的生产结论。

## 本项目的取舍

Mesotes 选择更容易解释的链路：本地规则优先，无法确定时调用管理员配置的轻量任务分析器；先执行能力和高风险过滤，再在满足 Route 质量门槛的候选中比较完整成本。所有候选、视觉模型、任务分析器、强基线和质量评审模型都必须来自当前 Profile。

> [!TARGET]
> 外部机制只有在被编译成有限配置、纳入统一预算并通过本项目测试后，才算进入实现范围。
