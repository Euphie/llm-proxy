# Profile 配置与模型角色

> [!CURRENT]
> 智能路由按 Profile 单独启用。未开启时，现有显式模型转发、视觉和重试行为保持独立，不会因为模型目录存在就自动路由。

## 启用 auto 的必要配置

一个 Profile 要使用 `model=auto`，至少需要：

1. 勾选参与路由的模型；新增模型默认不加入。
2. 指定一个强模型基线，作为不确定、高风险和路由异常时的安全选择。
3. 指定一个轻量任务分析器，用于本地规则无法确定的请求。
4. 保存一份有效策略配置；策略内必须包含任务类型到 Route 的映射和一个默认 Route。后续修改通过
   独立草稿、评估、灰度和发布流程上线。

视觉模型、动态策略优化和质量评审模型是可选能力；但一旦开启对应功能，其必需模型和预算就不能为空。

## 四个核心对象

### Profile

Profile 是 URL 入口、协议、上游配置和路由配置的共同边界。一个请求进入 Profile 后，不能再选择其他 Profile 的模型或资源。

### ModelCard

ModelCard 描述“这个逻辑模型能做什么、容量多大、价格多少”，主要字段包括：

- 模型 ID、提供方和生命周期；
- `context_window`、`max_output_tokens`；
- 视觉、工具、结构化输出等能力；
- 输入、输出和缓存等价格维度；
- 质量证据和更新时间。

系统可根据模型 ID 智能匹配内置资料并给出候选，但必须由管理员确认后保存。

未知值不能被当成“可能支持”：未登记或未确认的能力不满足对应硬约束。任何在已启用功能中可能被调用的模型，如果缺少计算完整成本所需的价格字段，配置或策略不能发布；价格为零是有效值，字段缺失才表示未知。

### Target

Target 表示“当前 Profile 中实际要调用的端点”。Upstream 是支持全部目录模型的 primary；备用 Target
按顺序配置 endpoint 和精确模型列表。主 Target 与备用项用结构化供应商 ID、凭据范围建立兼容边界，
备用值必须精确匹配；所有 Target 继承 Profile 协议。执行计划只为当前 Profile、同一逻辑模型冻结
通过校验的端点，不支持跨 Profile 或跨供应商调度。

### Route 与 Strategy

Route 是策略中的任务类别，例如“代码修改”或“低延迟问答”；它定义候选、硬约束、质量门槛和成本偏好。一个 Profile 同时只有一个 active Strategy，Strategy 内含多个 Route、任务类型映射、一个必填的默认 Route，以及一份统一 Request/AttemptBudget。预算在 Route 映射前创建并供任务分析器消费；Route 不能另设更宽松的预算。本地规则或轻量分析器得到任务类型后映射到 Route，没有匹配时使用默认 Route。

## 模型角色

- **参与模型**：`auto` 可以选择的普通候选。
- **强模型基线**：不确定或高风险时的保底，也是质量比较参照。
- **轻量任务分析器**：只在规则无法判断时识别任务类型、复杂度和风险。
- **视觉模型**：主模型不支持视觉时，把图片转成与当前问题相关的描述。
- **质量评审模型**：仅在开启动态策略优化时，对去标识后的候选结果做异步比较。

同一个模型可以承担多个角色，但每次调用都要计入对应预算和对应成本：在线任务分析、视觉和主回答计入请求预算与请求完整成本；响应后的质量评审计入独立评测预算与评测成本。

## 上下文参数

`context_window` 是模型真实上下文容量；`client_context_window` 是给 Agent 配置的保守可用窗口，应扣除输出、工具、视觉描述和协议预留。代理不负责压缩、截断或总结上下文，只提供正确的配置建议。
