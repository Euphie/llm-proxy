# 实施范围与交付

> [!TARGET]
> Phase 1、Session 连续性、独立策略生命周期、异步对比学习和带结构化信任边界的有序多 Target 容错已完成。

## v1 边界

- 单进程、单副本部署，SQLite 保存 Profile、模型目录、策略和统计。
- Profile 是永久边界，禁止跨 Profile 路由、回退、评测或部署。
- Upstream 是 primary；备用 Target 只有在供应商、凭据范围与 Profile 协议兼容后，才在当前 Profile
  内按模型和静态顺序使用。
- 项目不管理密钥；凭据只透传，异步任务最多在内存保留 10 分钟。
- 不持久化原始 prompt、图片、完整响应或凭据。
- 不做分布式协调、自动发布、强化学习或 Bandit。
- 不由代理压缩、截断或总结 Agent 上下文。

这些选择会形成新的配置与数据模型，不保证旧设计文档或未发布 schema 的兼容性；实施前应以本版合同为准清理残留。

## 三个实施阶段

### 第一阶段：可用的 auto（已实现）

实现 Profile 开关、参与模型、强模型基线、轻量任务分析器、本地规则、高风险过滤、视觉三态、不可变 ExecutionPlan 和统一 AttemptBudget。完成后应能安全处理显式模型与 `auto`：分析器异常时优先回到强基线，强基线不满足全部硬约束时明确失败。

### 第二阶段：可运营（已实现）

Session 升级不降级、路由轨迹、完整计划成本、不可变策略版本、CAS 发布、稳定 canary、LKG 回滚、原子热加载和配置 A/B/C/D 展示等级已实现。自动健康回滚仍留在后续阶段。

### 第三阶段：可优化（部分已实现）

异步内存队列、盲化质量评审、时间衰减保守估计、候选策略草稿，以及同一 Profile、同一供应商
的有序多 Target 容错已经实现。系统可以积累证据降低成本，但仍由管理员决定发布。Target 主动
健康探测和容量调度不在当前范围内。

### 当前视觉生命周期（已实现）

入口操作感知解析与改写、图片来源/视觉传输兼容过滤、回答/视觉 Target 交集，以及主回答前临时
视觉故障的兼容 Target/模型回退已实现。完整最坏调用图和覆盖视觉、切换、回答的复合原子预算
预留仍是后续阶段，当前文档不把统一 AttemptBudget 等同于这项能力。

## 关键验收

1. `model=auto` 配置不完整时明确失败，显式模型不受影响。
2. 任一执行计划只含一个 Profile；禁止跨 Profile 候选和回退。
3. 本地规则无法判断时才调用分析器；失败、超时或低置信度优先选择强基线，强基线不满足全部硬约束时明确失败。
4. 视觉三态正确，未启用或未配置视觉模型时不发送辅助请求。
5. 所有在线出站调用都计入 AttemptBudget；ClientCommit 后不再重试。
6. Session 只因永久能力不足升级，临时故障不改绑定，系统不自动降级。
7. 动态优化队列不阻塞线上请求，满时丢弃，凭据和正文不落库。
8. 质量等级只展示，Route 严重错误门槛不能被分数绕过。
9. 发布 CAS、热加载和 LKG 回滚在并发与失败场景下保持一致。
10. 未知能力不能通过硬约束；启用功能所需模型缺少价格时禁止发布；普通候选质量证据不足时使用保守先验。

## 交付物

每个阶段都应同时交付配置 UI、校验规则、运行时代码、数据库迁移、日志指标和测试。只有对应测试通过后，文档状态才能从“待实现”改为“已实现”。
