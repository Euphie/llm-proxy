# 异步评测与策略优化

> [!TARGET]
> 动态策略优化默认关闭。它的作用是收集“低成本模型在哪些任务上也能胜任”的证据，并生成候选策略；它不影响当前请求，也不自动发布。

## 开启条件

管理员开启动态策略优化时，必须同时配置：

- 异步样本比例；
- 每日评测预算；
- 质量评审模型；
- 当前 Profile 的参与模型和强模型基线。

缺少任一必需项就不能开启。只有成功完成的 `model=auto` 请求可以进入采样。

## 异步流程

```text
线上请求完成
  -> 按比例采样
  -> 写入有界内存队列
  -> 候选模型与强基线生成结果
  -> 先做格式、工具等确定性检查
  -> 对去标识的 A/B 结果做质量评审
  -> 更新统计证据
  -> 生成候选策略
```

队列满时直接丢弃样本，不能阻塞线上响应。任务受独立并发、单次超时和每日金额预算限制。当前
版本排除高风险和工具调用任务，避免异步副作用。

## 凭据与数据

项目不管理评测密钥。异步任务只可复用触发请求的透传凭据，并且只保存在当前进程内存中，最长 10 分钟；进程重启后任务自然丢失。不得把凭据、prompt、图片或完整输出写入 SQLite、日志或策略版本。

由于 v1 使用内存队列，这是一种尽力而为的优化：样本可以被丢弃，不能承诺必达或跨重启恢复。

## 如何形成质量证据

候选和强基线的结果先去掉模型身份并随机交换 A/B 顺序，再交给质量评审模型做主观比较；结构化
输出和明显错误优先使用确定性检查。最终按 Route 和任务类型累计胜负、严重错误、成本和延迟。
系统以策略中的质量事实作为先验，让旧样本按 30 天半衰期衰减，并计算单侧 95% 保守区间；有效
样本不足 20 时只展示“积累中”，不能生成学习候选。

质量评审模型并不决定线上回复，也不会把自己的内容注入主回答。视觉描述缓存与评测统计相互独立；缓存只有在 Profile、图片、视觉模型、传输方式、提示词、当前问题上下文和鉴权域组成的完整键一致时才可跨请求复用。

## 候选策略

评测只生成新的 draft。管理员可以看到样本量、保守区间、成本和严重错误，再决定是否载入草稿、
开始评估和进入灰度。系统不能自动把候选变成 active。

> [!CURRENT]
> 当前运行时已经实现按 Profile 隔离的异步内存队列、每日预算、确定性检查、盲化质量评审、
> 保守证据估计和学习候选草稿。异步任务会按模型使用其首个计划 Target；跨 Target 质量比较和
> 自动发布不在当前范围内。
