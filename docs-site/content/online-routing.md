# 在线路由

> [!CURRENT]
> 在线路由只处理当前请求。它不会现场训练策略，也不会在 Profile 之外寻找模型。

## 从请求到执行

```text
Profile -> 入口 / 请求级预检 -> 请求特征 -> 本地规则
                                      -> 无法确定时调用轻量任务分析器
         -> task_type 映射 Route -> 高风险则检查强模型基线
                                  -> 其他请求做候选能力过滤与成本选择
         -> 视觉计划 -> 不可变 ExecutionPlan -> 执行
```

![在线路由流程](/diagrams/routing-pipeline.svg)

图示等价说明：请求先在当前 Profile 内完成协议、安全和结构预检，再提取特征并运行本地规则；只有结论不明确时才调用轻量任务分析器。得到的任务类型映射到当前策略的 Route；高风险请求只检查强模型基线，其他请求再按能力、上下文、视觉等候选硬约束过滤并做成本选择。最后确定视觉处理方式，生成不可变 ExecutionPlan，并按剩余请求预算执行。

## 支持的操作

v1 的 `model=auto` 只支持 Anthropic `POST /v1/messages`，以及 OpenAI `POST /v1/chat/completions`、`POST /v1/responses`。入口路径决定唯一操作，适配器不会根据正文中碰巧出现的 `messages` 或 `input` 猜协议。图片、任务文本和实际工具操作共享同一份操作感知解析结果：只读取协议位置，忽略其他字段中的同名嵌套对象；Responses 字符串 `input`、easy-message 字符串 `content` 和直接 `input_text` 都用于任务分析与 Token 估算。其他方法或路径使用 `auto` 时返回明确的 unsupported operation 错误；显式模型继续沿用当前透传行为。

## 显式模型与 auto

显式模型请求保留调用方选择，不进入智能选模。`model=auto` 才读取当前 Profile 的参与模型、强模型基线和策略配置。Profile 未开启智能路由或配置不完整时，`auto` 返回配置错误，不静默猜测模型。

## 本地规则优先

本地规则负责低成本、可确定的判断，例如：

- 是否包含图片、实际/强制工具操作或结构化输出；
- 估算上下文是否接近模型容量；
- 是否命中管理员定义的高风险场景；
- 是否明显属于简单改写、摘要或分类任务。

只有规则无法稳定判断时，才调用轻量任务分析器。分析器返回任务类型、风险和置信度，不直接指定任意模型。任务类型按 active 策略映射到 Route；没有匹配时使用必填的默认 Route。分析器失败、超时或置信度不足时先按错误分类处理：网络故障、过载、畸形输出或低置信度优先选择当前 Profile 的强模型基线；如果强基线也不满足能力、上下文、视觉或安全硬约束，则按入口协议明确失败。分析器的 401/403、不可重试 4xx 和重定向/协议响应是硬失败，不进入强基线回退。

## 高风险规则

Profile 的高风险策略包含四个确定性维度：规范化用户/任务文本中的敏感子串、实际或命名强制
工具操作名中的敏感子串、可选的结构化输出规则，以及输入估算加请求输出相对强模型上下文窗口
的比例。子串不区分大小写且不执行正则；缺失列表使用内置保守默认，显式空列表停用对应维度，
缺失或零阈值默认 75%。仅声明 `tools` 不触发高风险，但仍是候选模型能力约束。

Anthropic assistant `tool_use`、Chat assistant `tool_calls[].function.name`、Responses
`function_call` 输入项以及三者的命名 `tool_choice` 才属于实际/强制操作。其余敏感意图交给分析器；
分析器不得把工具可用性本身视为高风险。命中任一确定性规则或高置信风险结论后，强制使用满足
全部硬约束的强模型基线；强基线不满足时明确失败，成本排序不能覆盖这条规则。

输入 Token 约按 canonical JSON 的每四字节一个估算。协议图片块中的原始 base64 payload 会
替换为短标记，避免多 MB 图片字节抬高成本或上下文路由；周边 JSON、用户文本、工具 schema、
普通 URL/文件引用及协议位置外的相似字段仍计入估算。路由轨迹不保存任务文本或工具参数。

> [!CAUTION]
> 行为变更：仅广告工具定义不再自动视为高风险；旧配置缺失结构化输出高风险开关时按关闭处理。
> 缺失敏感列表与零阈值仍按上述默认值解析，不提供其他历史兼容层。

## 不可变 ExecutionPlan

一次决策完成后生成不可变 ExecutionPlan，至少固定：Profile、策略版本、主模型、Target、视觉方式、计划内尝试和 AttemptBudget。执行阶段只能沿计划前进，不能重新进入模型选择，也不能在循环外额外发送请求。

路由轨迹应记录规则结论、分析器是否被调用、候选排除原因、最终模型、预算消耗和 ClientCommit，但默认不保存 prompt、图片、凭据或完整输出。

> [!CURRENT]
> 当前运行时已实现该流水线和不可变 ExecutionPlan；管理后台统计页会展示最近的真实结构化路由轨迹。本站交互轨迹仍是用于解释字段的静态示例。

> [!FUTURE]
> 当前已支持同一 Profile 内的有序备用 Target；它不会改变规则优先、强基线回退和不可变计划这三条合同。
