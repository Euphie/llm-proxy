# 智能路由概览

> [!TARGET]
> 本页描述的是待实现方案。目标是在不改变 Agent 调用方式的前提下，让 `model=auto` 自动选择合适模型：简单任务优先低成本模型，复杂或高风险任务使用强模型，同时保留视觉增强和现有容错能力。

## 一句话理解

请求 URL 先选定一个 Profile，随后系统只在这个 Profile 已登记的模型中做选择：

```text
请求 -> 本地规则 -> 必要时轻量分析 -> 能力与风险过滤
     -> 选择满足质量要求且预计总成本更低的模型 -> 执行
```

整个过程中，路由、视觉辅助、重试、Session 和异步评测都不能越过当前 Profile。

## 两种调用方式

- `model=<明确模型>`：保持调用方指定的逻辑模型，不做智能选模，只执行能力检查和该模型的正常转发。
- `model=auto`：使用当前 Profile 的已发布策略选择模型。只有管理员为该 Profile 显式开启智能路由后才可用。

开启 `auto` 至少要配置参与模型、一个强模型基线、一个轻量任务分析器和一份已发布策略。新增模型不会自动加入候选。

## 设计原则

1. **先守边界**：URL 选定 Profile 后，禁止跨 Profile 路由、回退、视觉调用、评测或部署。
2. **先过滤再优化**：能力、上下文、工具、视觉和高风险要求是硬条件，价格不能绕过它们。
3. **规则优先**：明显简单或明显高风险的请求由本地规则判断；只有拿不准时才调用轻量任务分析器。
4. **安全回退**：任务分析器失败、超时或置信度不足时，优先使用当前 Profile 的强模型基线；强基线也不满足能力、上下文、视觉或安全硬约束时，明确失败。
5. **成本要算完整**：任务分析、主回答、视觉辅助、重试和模型切换都计入一次请求的预计总成本。
6. **学习不改线上**：异步评测只生成候选策略，不能自动发布或直接改变当前请求。

## 这版不做什么

- 不管理或长期保存上游密钥，只透传当前请求凭据。
- 不让代理压缩、截断或总结 Agent 上下文。
- 不自动把新模型加入路由，也不自动发布学习结果。
- 禁止构建跨 Profile 或跨供应商的全局模型市场。
- v1 不做多副本协调、强化学习或 Bandit。

> [!CURRENT]
> 当前运行时已经有 Profile URL、协议转发、视觉预处理、重试和统计等基础能力，但尚未实现本文描述的 `model=auto`、统一尝试预算、Session 选模连续性和动态策略优化。

> [!FUTURE]
> 首版稳定后，可在不突破 Profile 边界的前提下增加同供应商多 Target 调度和更丰富的离线策略生成算法。
