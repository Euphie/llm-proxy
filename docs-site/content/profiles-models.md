# Profile 与模型目录

> [!CURRENT]
> Profile 是连接、模型、请求、Session、评测、策略和统计的永久隔离边界。

## Profile 是隔离边界

Profile 由 URL 选择。请求正文、模型名或 Header 都不能改写 URL 已选定的 Profile。智能路由、视觉、重试、评测和回退只能使用该 Profile 的连接与模型。

不同 Profile 可以共享同一进程和数据库，但不能共享以下运行事实：

- Routing Policy 和候选集合；
- Session 分类、模型绑定和锁定状态；
- 模型表现、本地评测和 Production 资格；
- 视觉缓存的鉴权作用域；
- 路由轨迹和费用聚合。

如果业务需要共享一个上游网关，应分别在各 Profile 中明确配置；禁止跨 Profile 回退。

## 连接配置

每个 Profile 固定一种协议和一个 Upstream。Upstream 应能处理该 Profile 目录中的所有模型；节点级负载均衡、健康检查、熔断、区域选择和故障转移由网关负责。

代理按当前请求透传鉴权，不把调用方输入的临时密钥保存为 Profile 配置。Agent 配置页面也只在浏览器中生成带占位符的客户端示例。

## 模型目录记录什么

| 模型事实 | 运行时用途 |
| --- | --- |
| 精确模型 ID | 原样发送给 Upstream，区分大小写 |
| 上下文窗口、最大输出 | 检查请求和计划是否可执行 |
| 视觉、工具、结构化输出 | 作为不可补偿的硬能力 |
| 输入、输出、缓存读写价格 | 估算最坏费用和已知实际费用 |
| `available` / `offline` / `retired` | 控制新请求是否可以选择 |
| 来源与更新时间 | 区分本地覆盖和目录快照 |

模型目录是事实层，不保存模型权重、上游节点或密钥。Routing Policy 只引用事实，不应复制一套能力与价格。

## 能力事实如何参与路由

`model=auto` 在评分前先检查：

1. 模型属于当前 Policy 的参与模型；
2. 目录状态是 `available`；
3. 上下文与最大输出满足请求；
4. 图片、工具和结构化输出能力满足硬要求；
5. 成本门槛所需价格事实完整。

任意硬能力失败都会排除候选。低价、低延迟或高质量分不能补偿硬能力缺失。

## 价格字段的解释

价格以每百万 Token 的微美元整数保存。零是有效价格；字段缺失表示未知，而不是免费。

一次请求的完整成本可能包含：任务分析、未命中缓存的视觉、主回答、同模型重试和模型切换。只录入回答模型价格仍可能让整条请求费用未知。

## 模型目录修订

每次保存模型事实或状态都会产生新的模型目录修订。Routing Policy 保存时校验当前目录引用；后续请求读取新的运行时修订，在途请求保持原快照。

这带来两个直接结果：

- 更新模型配置后无需重启服务；
- 在途请求不会一半使用旧价格、一半使用新能力。

后台使用期望修订号处理并发保存。冲突表示当前页面基于旧快照，必须刷新后重新编辑。

## 引用保护

模型可能被以下位置引用：参与模型、任务分析模型、强模型基线、评审模型、Route 候选和视觉模型。破坏性变更前，后台会检查这些关系。

替换顺序应为：新增新 ID → 补齐事实 → 更新 Policy/视觉引用 → 验证新请求 → 旧 ID `offline` → 观察后 `retired`。不保留旧 URL 或旧模型名兼容别名。

## 识图模型的两种输入方式

视觉设置支持：

- 从当前已录入模型中选择，减少 ID 拼写错误；
- 手动输入 Upstream 已存在的精确模型 ID，适合只做辅助识图的部署。

手动输入不会自动补齐目录事实。如果希望该模型参与 `model=auto` 的能力、成本、Production 资格或执行计划校验，仍需将它录入模型目录。

## 状态如何使用

| 状态 | 新请求行为 | 适用场景 |
| --- | --- | --- |
| `available` | 可以继续作为候选 | 已验证且可服务 |
| `offline` | 不接收新请求，事实保留 | 临时故障、维护或观察期 |
| `retired` | 不接收新请求，作为退役记录保留 | 永久下线 |

状态只影响后续计划。已进入请求的冻结计划不会被后台状态变化原地改写，但执行仍受共享上下文取消和上游实际结果约束。

## 常见配置错误

- 模型 ID 大小写或部署名错误：上游立即返回不存在。
- 把缺失价格写成 0：费用看似完整，实际低估。
- 未声明工具或视觉能力：候选被保守排除。
- 直接退休被角色引用的模型：保存校验失败。
- 假设目录模型自动进入 Policy：新增模型仍不会接流量。
