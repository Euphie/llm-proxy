## 从现状到目标

| 当前状态 | 待实现目标 |
| --- | --- |
| URL 选择 Profile | URL 选定后，所有路由与辅助调用永久限制在该 Profile |
| 每个 Profile 一个 upstream | 增加 ModelCard 与 Target；v1 先保持每模型一个 Target |
| 普通重试循环 | 用统一 AttemptBudget 约束所有主回答和辅助调用 |
| 写头后直接流式转发 | 首个完整合法协议事件形成 ClientCommit，提交后不再重试 |
| usage 统计 | 增加路由原因、尝试、完整成本和质量证据 |
| 配置热替换基础 | 增加不可变策略、CAS 发布、灰度和 LKG 回滚 |

> [!TARGET]
> 本次方案保留现有 Profile、视觉和容错能力，新增的是可解释、可控成本、可安全回滚的 `model=auto`。实现时应逐阶段交付，不能用文档状态替代运行时测试。

## 判断文档是否过时

每当运行时能力变化，应同时更新固定源码基线、差距表和验收项。没有对应代码与测试证据的能力仍标记为“待实现”。
