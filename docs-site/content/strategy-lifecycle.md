# 策略生命周期

> [!TARGET]
> 策略发布是管理员可控的显式操作。动态优化可以提出候选，但不能自动替换线上 active 策略。

## 命名与状态

策略的规范名称使用日期加序号，例如 `20260801-001`；管理员可以再设置容易理解的别名，例如“代码助手-均衡版”。别名只用于展示，引用和审计始终使用不可变策略 ID。

```text
draft -> evaluating -> ready -> canary -> active
                              \-> rollback
```

![策略生命周期](/diagrams/strategy-lifecycle.svg)

图示等价说明：草稿校验后生成不可变版本，经过评测和人工确认进入灰度，再由管理员提升为 active。发布使用 CAS 防止并发覆盖；自动动作只允许回滚到 last-known-good，不允许自动提升候选策略。

## 不可变版本

Draft 可以修改；一旦发布成策略版本，其参与模型、模型角色、Route 门槛、价格快照、AttemptBudget 和选择规则都不可原地更改。修改必须产生新版本，保证历史路由轨迹可以解释。

## 热加载

发布时先校验完整配置，再用 CAS 原子切换 active 指针。运行时监听版本变化，加载成功后一次性替换只读快照：

- 新请求使用新快照；
- 已进入执行的请求继续固定旧快照；
- 加载失败保留 last-known-good，不暴露半成品。

## 灰度与回滚

管理员设置 canary 比例并观察 Route 质量门槛、完整成本、严重错误和稳定性。提升为 active 必须手动确认。若命中已授权的可靠性硬门槛，系统可以自动 CAS 回滚到精确的 last-known-good；没有可用 LKG 时停用 `auto` 并返回明确错误。

## 紧急停用模型

模型安全、账单或上游故障需要快速处置时，管理员可以立即禁用模型。紧急禁用优先于旧策略快照，新的出站调用不得继续选择该模型；已产生 ClientCommit 的请求仍按协议结束，不能重放。

## 可观测性

每次 `auto` 记录策略 ID、Route、规则结论、分析器状态、候选排除原因、最终模型、尝试次数、完整成本和 ClientCommit。默认不记录原始 prompt、图片、凭据或完整响应。

> [!CURRENT]
> 当前原子 Registry 快照替换可作为热加载基础；策略状态机、CAS 发布、灰度和 LKG 仍待实现。
