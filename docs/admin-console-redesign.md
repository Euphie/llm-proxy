# 管理后台新手体验与信息架构重组

## 实现状态

已实现概览、四步首次接入、Profile 分区路由、共享依赖判断、模型引用保护、停用配置保留和桌面/窄屏布局。现有成熟字段编辑逻辑继续由 `profiles.js` 提供，详情外壳只把当前分区挂载到页面；后续可以继续按功能拆分源码，但不影响当前交互。

## 目标

管理后台应让第一次使用 llm-proxy 的管理员在 5 分钟内完成以下闭环：

1. 创建并启用一个可加载的 Profile。
2. 为本地 Agent 生成配置。
3. 从 Agent 发起真实请求。
4. 在后台确认请求已经到达。

高级能力不得阻塞基础代理。后台不保存调用方密钥，也不会用缺少真实凭据的服务端探测冒充上游连接测试。

## 当前问题

- 登录后直接进入 Profiles，新用户不知道 Profile 与代理地址的关系。
- Profile 编辑器把基础连接、模型、智能路由、视觉、上游节点、重试和 Agent 配置放在一个超长表单中。
- 前置条件主要在保存时由后端报错，用户无法提前理解功能依赖。
- Session 已能返回 `profile_setup_required`，界面却没有使用该状态。
- Profile 列表已有请求统计，界面却没有把“收到首个真实请求”作为上手完成标准。

## 信息架构

全局导航调整为：

| 页面 | 路径 | 作用 |
|---|---|---|
| 概览 | `/_admin/` | 运行状态、上手进度、Profile 摘要、最近用量和快捷操作 |
| Profiles | `/_admin/profiles` | 创建、复制、启停和选择 Profile |
| 统计 | `/_admin/stats` | 用量和智能路由调用明细 |
| 系统 | `/_admin/system` | 密码、版本、数据目录和导出 |

Profile 使用独立详情页，不再使用一个长表单：

| 分区 | 路径后缀 | 内容 |
|---|---|---|
| 概览 | `overview` | 状态、代理地址、依赖提醒、用量和快捷操作 |
| 基础连接 | `connection` | 名称、Slug、协议、Upstream、启用和默认项 |
| 模型 | `models` | 模型目录、能力、上下文和价格 |
| 智能路由 | `routing` | 参与模型、角色、风险、策略、预算和对比学习 |
| 视觉增强 | `vision` | 视觉模型、传输、缓存、限制和提示词 |
| 容错 | `reliability` | 备用上游节点和普通重试规则 |
| Agent 配置 | `agents` | Claude Code、OpenCode 和 Codex 配置生成 |

完整路径为 `/_admin/profiles/{id}/{section}`。未知 Profile 或分区显示可恢复的 404 页面，并提供返回 Profiles 的入口。

## 首次配置

Session 为 `profile_setup_required` 时进入 `/_admin/setup`：

1. **基础连接**：填写名称、Slug、协议和 Upstream；第一个 Profile 自动启用并设为默认。
2. **模型能力**：选填；支持粘贴模型 ID 自动填写，也允许跳过。
3. **Agent 配置**：只显示与 Profile 协议兼容的 Agent，生成内容仍只存在浏览器内。
4. **验证使用**：显示精确代理地址和操作说明，轮询该 Profile 的现有统计，检测首个真实请求。

Profile 创建成功后每一步都可退出。刷新页面时不恢复瞬时表单，而是根据服务端事实决定下一项：

- 没有 Profile：回到基础连接。
- 已有 Profile，但请求总数为零：概览继续提示生成配置和发送请求。
- 已有请求：上手流程完成，默认进入概览。

首个请求通过 `GET /_admin/api/stats?profile_id={id}` 的全量 `summary.requests` 判断，不新增数据库字段，也不会因 30 天统计窗口过期而重新进入新手状态。

## 功能依赖

前端使用一个纯函数模块计算每项功能的 `ready`、`blocked`、`disabled` 和 `attention` 状态。概览、首次配置、Profile 导航和各分区共享同一结果。

| 功能 | 硬性前置条件 |
|---|---|
| 基础代理 | Profile 已保存，协议和 Upstream 有效 |
| Agent 配置 | Profile 已保存；模型目录选填 |
| 普通重试 | 基础连接有效；规则允许为空 |
| 智能路由 | 已录入模型；参与模型、强模型和任务分析模型来自模型目录；所有实际调用模型具备输入与输出价格 |
| 策略生命周期 | Profile 已保存并启用智能路由 |
| 对比学习 | 智能路由已启用；仲裁模型已录入，并具备价格、上下文和最大输出能力 |
| 备用上游节点| 已录入模型并启用智能路由；上游节点只引用已录入模型，供应商与凭据范围和主上游节点一致 |
| 视觉增强 | 已填写视觉模型；智能路由同时启用时，视觉模型还必须录入并具备视觉、价格、上下文和最大输出能力 |

依赖未满足时，功能入口保持可见，但显示缺失项和直达操作，例如“先录入模型”。不能只显示一个不可解释的禁用开关。

## 引用安全

模型目录是智能路由、视觉和备用上游节点的事实来源：

- 删除模型或修改精确 ID 前，计算全部引用位置。
- 存在引用时阻止操作，并列出引用该模型的角色、Route、视觉配置和上游节点。
- 用户必须先重新选择引用模型或关闭相关功能。
- 不静默替换模型，不按近似名称自动改写已保存引用。
- 模型推荐只辅助录入能力，不改变精确 ID 的运行时语义。

关闭智能路由、视觉增强或对比学习只设置 `enabled=false`，保留其他已填写配置。重新开启时重新计算依赖并阻止无效保存。此行为会改变当前“关闭 Auto 或对比学习时丢弃其详细配置”的前端序列化方式。

## 页面行为

### 概览

概览按优先级展示：

1. 运行状态：未配置、可用、需要处理或运行时异常。
2. 上手卡片：下一项操作及唯一主按钮。
3. Profile 摘要：启用、默认、协议、代理路径、功能状态和请求数。
4. 最近用量与统计入口。

已经完成上手的用户不再看到占据首屏的大型新手说明，只保留紧凑状态摘要。

### Profile 编辑

- 全局侧边栏和 Profile 二级导航同时保留当前位置。
- 每个分区只渲染当前任务相关字段，并有独立保存按钮。
- 前端始终基于最新完整 Profile 生成 PUT 请求，只替换当前分区负责的字段。
- 切换分区或离开页面前若存在未保存修改，使用原生确认提示。
- 后端无法映射到字段的错误显示在当前分区顶部，并提供相关分区入口。

### 响应式与可访问性

- 桌面端使用 macOS 设置式双层侧边栏；窄屏将 Profile 导航改为紧凑顶部网格。
- 新手步骤使用语义化有序列表和 `aria-current="step"`。
- 锁定状态包含文字原因，不能只依赖颜色或锁图标。
- 页面切换后聚焦主标题；异步保存和首个请求检测使用非打断式 live region。
- 所有操作可通过键盘完成，并保持现有颜色对比要求。

## 前端模块

当前 `profiles.js` 需要拆分，避免继续在单个 3000 行文件中增加状态：

| 模块 | 职责 |
|---|---|
| `dashboard.js` | 概览与上手状态 |
| `onboarding.js` | 首次配置步骤与请求检测 |
| `profile-readiness.js` | 依赖、引用和下一项操作的纯函数 |
| `profile-draft.js` | Profile 草稿、分区合并和完整 Payload |
| `profile-editor.js` | 详情外壳、二级导航、依赖提示和未保存修改保护 |
| `profile-models.js` | 模型引用安全 |
| `profiles.js` | 现有字段编辑、模型推荐、路由、视觉、容错与 Agent 入口 |

现有 `api.js`、`generator.js`、`stats.js` 和 `system.js` 继续复用。此阶段不引入前端框架、构建链或新的数据库表。

## 错误与并发

- 页面使用 loading、empty、ready 和 error 四种明确状态。
- 401 继续统一返回登录页，密码字段不得保留。
- Profile 保存仍以服务端验证为最终边界，前端依赖检查不能替代后端校验。
- 当前系统只有一个管理员账号，保持完整 Profile PUT 的更新模型；本次不引入字段级 API 或配置版本冲突协议。
- 请求检测仅在验证页面可见时轮询，离开页面或文档隐藏后停止，并保留手动刷新。

## 兼容性影响

- 登录后的默认页面从 Profiles 改为概览。
- `/_admin/profiles` 保留；旧的 Profile 编辑器内部状态不作为兼容接口。
- 关闭 Auto 或对比学习后将保留其详细配置，不再清空。
- 被引用模型不能直接删除或修改 ID。
- 不改变代理 URL、Profile API、数据面协议、密钥透传和现有数据库结构。

## 验收标准

1. 没有 Profile 的管理员修改初始密码后自动进入首次配置。
2. 只填写四个基础字段即可创建可加载的默认 Profile，高级功能不阻塞保存。
3. 用户可以跳过模型配置并生成兼容 Agent 配置。
4. 实际请求到达后，验证步骤和概览无需人工标记即可显示完成。
5. 已有用户登录后进入概览，并能在两次操作内到达任一原有功能。
6. Profile 编辑不再同时显示七个大区块。
7. 智能路由未满足模型依赖时不能启用，并能直达缺失配置。
8. 删除或修改被引用模型时，界面列出引用并阻止操作。
9. 关闭再开启功能不会丢失详细配置。
10. 桌面和窄屏均可完成首次配置、分区保存和 Agent 配置生成。

## 验证

- `profile-readiness` 的依赖矩阵、引用检查和下一项操作单元测试。
- 无 Profile、已创建未请求、已收到请求三条上手流程测试。
- 每个分区只修改所属配置、完整 Payload 保留其他分区的回归测试。
- 关闭再开启功能保留配置的测试。
- 路径解析、未知 Profile、未知分区、浏览器前进后退和未保存提醒测试。
- 登录、密码轮换、Profile 生命周期、统计和 Agent 生成现有测试继续通过。
- Go 全量测试、Race、Vet、前端测试和桌面/窄屏真实浏览器冒烟测试。
- 更新 `docs/admin.md` 和 `docs/profiles.md`，使文档流程与新后台一致。
