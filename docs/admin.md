# 管理控制台

管理控制台位于 `/_admin/`，包含 Profiles、统计和系统三个页面。

## 首次登录

首次启动使用账号 `admin`、密码 `admin` 登录，然后按页面提示设置至少 10 个字符的
新密码。

## 后台使用流程

### 1. 创建 Profile

进入“Profiles”，点击“创建第一个 Profile”或“新建 Profile”：

1. 填写名称和 slug。slug 会成为公开代理 URL 的路径前缀。
2. 选择与 Upstream 一致的 `anthropic` 或 `openai` 协议。
3. 填写 Upstream 基础地址，不要包含调用方密钥。
4. 保存 Profile。第一个 Profile 会自动成为默认项，后续保存会立即热更新运行时。

默认 Profile 使用 `/v1/...`；指定 Profile 使用 `/<slug>/v1/...`。例如 slug 为
`coding` 时，Anthropic Messages 地址为 `/coding/v1/messages`。

### 2. 配置模型与视觉增强

“模型能力”是选填项。粘贴已收录的模型 ID 会自动填写容量、工具/结构化输出/视觉能力和
参考价格；保存前可以人工调整。`支持视觉 = 否` 表示该主模型可使用图片增强，
`支持视觉 = 是` 表示图片直接交给主模型。

需要图片增强时：

1. 打开“启用视觉预处理”。
2. 在“识图模型”中填写 Upstream 实际支持的视觉模型。
3. 选择未收录模型的处理方式。
4. 如有需要，在“视觉参数”中调整 Token、超时、并发、缓存或提示词。

启用智能路由后，识图模型还必须在模型能力目录中明确标记“支持视觉”，并填写足够的上下文窗口
与最大输出上限；保存会校验配置的描述输出和单图提示预留能放入窗口。OpenAI Chat 视觉传输不
支持 `file_id`，包含此来源的 `auto` 候选会在规划阶段被排除。

Profile 的过载规则按页面顺序匹配，命中第一条后按其重试次数和等待参数执行。
更完整的字段说明见 [Profiles](profiles.md) 和[图片预处理](vision.md)。

### 3. 启用智能路由

只有客户端发送 `model=auto` 时才会智能选模；显式模型请求不受影响。配置顺序如下：

1. 在“模型能力”中录入候选模型，并确认能力和输入/输出参考价格。
2. 打开“启用智能路由”，勾选参与模型；新录入模型不会自动加入。
3. 指定强模型基线和任务分析模型。强基线处理高风险或无法可靠判断的任务；分析模型只在
   本地规则拿不准时调用。
4. 设置策略名称、别名、默认 Route 和任务映射。每个 Route 配置候选模型、质量与严重错误
   门槛；系统只在达标候选中比较预计完整成本。
5. 设置统一尝试预算。任务分析、视觉、主回答、重试和模型切换都受同一总调用数、截止时间和
   最坏费用上限约束。
6. 如需同一 Agent 任务保持模型连续性，让客户端同时发送
   `X-LLM-Proxy-Session-ID: <稳定会话 ID>`。默认绑定 24 小时；只有请求带鉴权头时生效，
   Session ID 不会转发或落库。
7. 保存后让客户端请求 `model=auto`；在“统计”的“最近 Auto 路由”查看判断来源、模型路径、
   Target 路径、视觉方式、调用预算、计划上限、已消费估算、usage 已知实际费用和耗时。

如同一供应商为相同模型提供多个端点，先在“基础配置”为主 Target 填写逻辑供应商 ID 和凭据范围，
再在“Target 容错”中添加有序备用项：填写安全 ID、基础地址、与主 Target 精确一致的供应商 ID/
凭据范围，以及该端点实际支持的精确模型 ID；再把统一预算中的 Target 切换上限设为大于 0，并保证主回答
尝试上限足以覆盖切换。`model=auto` 遇到命中容错规则的故障时会先重试当前端点，再按页面顺序
切换备用 Target，最后才换模型。保存时会拒绝缺失、格式错误或不匹配的信任标识；这些字段不是
密钥。所有 Target 固定使用 Profile 协议，显式模型请求不会使用备用 Target。

含图片且需要增强时，系统只在同时支持回答模型和识图模型的 Target 交集中执行。主回答发出前的
临时识图故障可在统一预算内先切换兼容 Target、再切换计划内模型；鉴权、能力/请求协议和不可重试
4xx 错误立即停止。任务分析后会冻结完整最坏调用图；每个复合节点必须先原子预留视觉和首个回答
容量，才允许识图请求上网，缓存命中和未执行分支会释放未使用容量。

“容错规则”的状态码只接受 `408`、`425`、`429` 和 `500..599`。控制台和服务端都会拒绝把
`400`、`401`、`403`、`404`、`409`、`422` 等硬失败保存为重试或切换条件。

首次保存会把页面中的策略作为第一个正式版本。后续调整 Route 或统一尝试预算时：

1. 在“策略版本”中把上方当前参数保存为新草稿；版本名由系统按日期和序号生成。
2. 草稿可反复载入和修改；点击“开始评估”后版本不可再编辑。
3. 评估通过后设置灰度比例。只有带鉴权头的调用方会进入稳定灰度分组；同一调用方和
   Session 会保持在同一组，无法识别身份的请求继续使用正式策略。
4. 观察路由轨迹、成本和质量等级后，由管理员发布为正式策略；发布不会中断在途请求。
5. 新版本异常时点击“回滚到上一正式策略”。所有发布操作使用 revision 防止两个管理员互相覆盖。

灰度、发布、取消灰度或回滚失败时不会留下“后台已切换、请求仍使用旧策略”的半发布状态。
刷新页面获取最新 revision 后再重试；构建失败时原策略继续服务。

策略的 A/B/C/D 是基于当前人工配置事实计算的对比提示，只用于展示，不会绕过 Route 的质量和
严重错误硬门槛，也不会自动发布策略。

#### 可选：开启对比学习

需要让系统用线上样本验证低成本模型时，在智能路由区域开启“对比学习”：

1. 选择质量评审模型，并设置抽样比例、每日预算、并发数、队列容量和单次超时。
2. 保存后，系统只在成功、低风险且不含工具调用的 `model=auto` 请求结束后异步抽样。队列满、
   预算不足或任务过期时会直接跳过，不影响 Agent 的当前响应。
3. 在“策略版本”的学习证据中查看候选与强基线的样本量、保守质量下界、严重错误上界和当日费用。
4. 出现“证据可靠”后，点击“生成学习候选”。系统只创建草稿，不会自动改动当前正式策略。
5. 载入草稿检查 Route 参数，再按“开始评估 → 灰度 → 发布”的正常流程上线；不满意可直接删除草稿。

对比学习不保存问题、图片、完整回答或调用方凭据。凭据只在内存中短暂用于异步请求，进程重启后
未完成任务允许丢失。

任一必填角色、Route、候选能力或价格不完整时，Profile 会拒绝保存。字段定义和运行边界见
[智能路由](intelligent-routing.md)。

### 4. 生成 Agent 配置

在 Profile 列表点击“生成配置”：

1. 填写 Agent 能访问到的 llm-proxy 公网地址。
2. 选择 Claude Code、OpenCode 或 Codex CLI。
3. 选择全局、项目或命名配置目标，并填写模型映射。
4. 复制或下载生成结果，保存到页面标出的客户端路径。
5. 在 Agent 本地设置真实认证环境变量。

生成器不会保存公网地址、模型映射或密钥。Agent 支持范围和具体输出字段见
[模型能力与 Agent 上下文](models.md)。

### 5. 日常管理

- “Profiles”支持编辑、复制、启停、设为默认、策略版本管理和删除；Profile 公共配置保存后
  立即生效，线上策略只能通过灰度/发布流程切换。
- “统计”支持按 Profile、协议、模型、请求类型和时间筛选 Token 用量，并查看最近 Auto
  路由轨迹。
- “系统”支持修改管理员密码、查看运行信息和导出版本化 Profile JSON。
- Profile JSON 可用于审阅或迁移配置，不包含调用方密钥。

具体字段说明见 [Profiles](profiles.md)、[模型能力](models.md)、
[图片预处理](vision.md)和 [Token 用量统计](statistics.md)。
