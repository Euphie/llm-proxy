# 智能路由指标与决策设计

## 目标

智能路由在保持质量和稳定性门槛的前提下降低完整请求成本，并让管理员能够解释每次选型、模型表现和策略退化。

路由对象是完整执行方案，而不只是模型：文本请求通常是主模型；图片请求可以是原生视觉模型，也可以是“视觉增强模型 + 非视觉主模型”。视觉增强、重试和切换产生的成本与延迟都计入方案。

## 决策流程

```text
请求事实与任务分析
  → 生成候选执行方案
  → 硬能力筛选
  → 质量、稳定性和严重错误门槛
  → 计算质量、稳定性、成本效率、性能四个一级指标
  → 按策略权重计算路由分
  → 冻结 ExecutionPlan 并执行
```

任务分析模型只输出任务类型、难度（`easy/medium/hard`）、风险和置信度，不直接选择模型。图片、工具、结构化输出、上下文长度等事实由请求解析器确定，不能被任务分析结果覆盖。专业领域不作为首版路由维度，避免模糊分类和样本稀疏。

图片不会自动升级到原生视觉主模型：

- 主模型支持视觉时生成原生视觉方案；
- 主模型不支持视觉且 Profile 已启用视觉增强时生成复合方案；
- 两条路径都不可用时才排除该模型。

## 策略配置

每个 Route 保存一组不可变的发布事实：

- 最低质量分；
- 最低稳定性分；
- 最高严重错误率；
- 质量、稳定性、成本效率、性能四个路由权重，总和必须为 100%；
- 每个候选模型的质量先验、稳定性先验、严重错误率先验和预期延迟。

内置三个可调整的权重模板：质量优先为 `55/25/10/10`，均衡为 `40/25/25/10`，成本优先为 `30/20/40/10`，依次对应质量、稳定性、成本效率和性能。严重错误率是独立硬门槛，不能被成本或综合分抵消。

候选通过门槛后，按以下结构计算最终分数：

```text
路由分 =
  质量分 × 质量权重
  稳定性分 × 稳定性权重
  成本效率分 × 成本权重
  性能分 × 性能权重
```

成本效率使用当前请求的候选计划成本计算，包含视觉增强和主回答；任务分析等所有候选共享的成本只计入完整请求总成本，不影响候选相对排序。候选成本效率为“最低候选成本 ÷ 当前候选成本”，零成本只与零成本候选同分。性能分采用同样的相对比例计算；预期延迟为零表示未知，固定按 50 分参与排序并在后台提示补充数据。

不再额外设置不确定性惩罚，贝叶斯保守边界已经包含样本不足的影响，避免重复惩罚。

## 动态指标

动态指标独立于 active 策略配置，不在请求过程中修改已发布策略。系统按 Profile、策略、Route、任务类型、难度、风险、候选模型、强模型基线和视觉模式聚合证据。

### 质量

盲评模型分别比较：

- 正确性；
- 完整性；
- 指令遵循；
- 格式与工具安全；
- 整体任务完成度。

评审只返回每个维度的 A 胜、B 胜或平局，以及两边是否存在严重错误，不返回主观的绝对百分制分数。系统对每个维度做贝叶斯更新，再按固定权重汇总为质量平均值和质量保守下限：正确性 40%、完整性 20%、指令遵循 20%、格式与工具安全 10%、整体任务完成度 10%。不适用的细项记为平局，不由评审模型随意改变权重。

### 稳定性

稳定性来自确定性检查和线上执行记录，包括：

- 请求成功率；
- 空响应和结构化输出失败；
- 超时、限流和上游错误；
- 重试、上游节点切换和模型切换；
- 严重错误率。

稳定性一级分按固定权重汇总：线上成功率 50%、无严重错误 25%、确定性输出有效率 15%、无重试或切换完成率 10%。稳定性展示平均值和保守下限；严重错误率展示平均值和保守上限。

### 成本与性能

系统展示平均完整成本、相对强模型节省比例、评测成本、P50/P95 总延迟、首选模型成功完成率和完整调用次数。评测成本单独展示，不混入线上节省结果。

### 可信度

每个动态指标同时展示原始样本、时间衰减后的有效样本、最近更新时间、趋势和可信等级。历史证据按 30 天半衰期衰减，先验强度为 20 个等效样本；有效样本达到 20 后才可用于生成学习草稿。

学习和后台观测使用单侧 95% 保守边界，而不是只使用平均值：质量和稳定性使用下限，严重错误率使用上限。在线路由只读取已发布策略快照；人工配置的初始值作为先验，学习草稿使用生成当时的保守边界，发布后才会影响在线选型。

### 主动升级校准

启用模型主动升级和异步对比学习后，系统按抽样结果累计：

- 有效升级：低级模型申请升级，异步比较确认强模型更好或低级模型存在严重错误；
- 无效升级：低级模型申请升级，但它原本的回答已经足够；
- 漏升：低级模型没有申请升级，但异步比较确认强模型明显更好。

后台展示升级准确率（有效升级 ÷ 已申请升级）和漏升率（漏升 ÷ 未申请升级的可评估样本）。
评估完全异步，费用计入独立评测预算，不增加在线响应等待时间，也不会直接修改 active 策略。

## 策略学习边界

动态指标可以触发后台退化警告，但不会自动修改、回滚或发布策略。管理员点击“生成学习候选”后，系统把可靠的质量下限、稳定性下限、严重错误上限和预期延迟写入一个新 draft；后续仍需人工评估、灰度和发布。

这一边界保证运行时只读取不可变策略快照，同时让新证据能够通过可审计的版本生命周期进入路由。

## 管理后台

Profile 的智能路由页面分为三层：

1. 当前策略：配置评分、动态评分、等级、趋势、样本覆盖、成本节省、延迟变化和退化警告；
2. Route 决策：门槛、四项权重，以及每个候选方案通过或未通过的原因；
3. 模型表现：按任务和视觉模式展示质量细项、稳定性、严重错误、成本、延迟、样本和可信度。

配置指标与动态指标必须使用不同标签和视觉样式，避免把管理员录入的先验误解为线上观测结果。策略版本页同时显示发布时评分和当前观测评分，但当前观测评分不改变版本内容。

每条 `model=auto` 路由轨迹保存本次决策使用的质量、稳定性、成本效率、性能和最终路由分，以及候选未通过的门槛原因；不保存请求正文、回答正文或凭据。

## 异常与回退

- 任务分析失败时沿用现有强模型基线回退和硬失败边界；
- 没有候选通过门槛时使用满足所有硬能力的强模型基线；
- 动态证据不足时使用已发布先验，并在后台标记低可信度；
- 动态指标查询失败不影响在线转发，只影响管理后台观测和学习草稿生成；
- 视觉增强失败、重试和模型切换继续受冻结的调用图、截止时间与成本预算约束。

## 验收

- 相同请求在不同权重策略下产生可预测且可解释的候选顺序；
- 非视觉主模型在视觉增强可用时不会被图片请求直接排除；
- 质量、稳定性或严重错误门槛不合格的便宜模型不能被选中；
- 少量样本不能产生虚假的高可信评分；
- active 策略不会因新证据自动变化，学习草稿包含证据快照；
- 后台能够查看策略总览、Route 决策明细和参与模型的动态表现；
- 关闭动态优化时不发送评测请求，在线路由仍使用发布策略工作。
