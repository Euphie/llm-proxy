# 模型目录管理设计

## 目标

模型目录同时支持批量录入和管理员手动远程更新。远程目录只提供推荐事实，不自动修改任何
Profile、运行策略或已保存模型参数。

## 批量录入

- 模型页接受一行一个模型 ID，单次最多 100 个。
- 空行和同批重复项自动移除；Profile 已存在的 ID 跳过且不覆盖。
- 点击“批量导入”后直接处理，不再增加预览确认步骤。
- 唯一可靠匹配自动填充参数；近似、多候选或未知模型只录入 ID，参数留空。
- 导入只写入当前 Profile 草稿，仍需点击 Profile 保存。

## 远程更新

- 系统页显示目录来源、revision、获取时间和模型数量，并提供管理员手动更新按钮。
- 服务端只访问固定的 Models.dev `models.json` 和 `api.json`，不接受自定义 URL。
- 下载具有独立超时和大小上限；模型结构、ID、能力、Token 与价格通过完整校验后才可使用。
- 更新结果原子写入 `DATA_DIR/model-catalog.json` 并立即用于后台推荐。
- 下载、校验、写入或启动加载失败时继续使用上一有效版本；没有有效文件时回退到内置快照。
- 不定时更新，不修改 Profile，不影响代理请求和在途策略。

## 潜在影响分析

更新后比较新旧目录中的上下文、最大输出、视觉、工具、结构化输出，以及输入、输出、缓存读取和
缓存写入价格。后台扫描所有
Profile 及其正式、灰度、评估和草稿策略，列出引用变化模型的模型角色、Route、视觉和备用
上游节点。报告只说明管理员以后采用新参数时的潜在影响，并提供对应 Profile 分区入口。

风险分级：

- 高：能力由支持变为不支持，或上下文、最大输出降低。
- 中：输入、输出或缓存价格变化，可能改变 Auto 成本排序。
- 低：容量提高、能力增加或其他推荐元数据变化。

## 智能路由依赖

启用智能路由时必须录入至少两个不同模型，并选择至少两个不同参与模型。强模型基线必须是
参与模型；任务判断模型可以复用任一已录入模型。前端用于提前提示，服务端保存校验是最终边界。

## 安全与验证

- 更新接口沿用管理员会话和 CSRF 防护，并限制为固定远程源。
- 远程响应不作为脚本执行，所有数据按 JSON 解码和白名单字段重建。
- 自动测试覆盖去重、匹配、未知模型、损坏快照、更新失败回退、影响引用和双模型约束。
- 浏览器验收覆盖批量预览、远程更新状态、影响报告和窄屏布局。
